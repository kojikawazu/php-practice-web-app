# テストルール

## テスト分類

| 分類 | 定義 |
|------|------|
| 正常系（Normal） | 期待通りの入力 → 正しい結果 |
| 準正常系（Semi-Normal） | 想定内の異常入力 → 適切なハンドリング |
| 異常系（Abnormal） | 想定外のエラー → 安全な失敗 |

## テストの粒度（分類と直交する軸）

上の分類（何を入れて何が返るか）とは別に、**どこまでのレイヤを通すか**を区別する。詳細・各アプリの実体は `docs/08` を参照。

| 粒度 | 定義 |
|------|------|
| 単体（Unit） | 1 レイヤ/クラスの契約を隔離して検証 |
| IT（統合／結合） | ルーティング→コントローラ→認証→データアクセス→実 DB を横断で検証 |
| E2E | ブラウザ自動化で UI から通しで検証 |

## 原則

- テストは仕様の証明。テストが失敗したら実装を修正する（テストを実装に合わせない）。
- 異常系（準正常系 + 異常系）が正常系を上回ることを目安とする。比率の数値目標より、**認可・境界値・不正入力**を優先的にカバーすることを重視し、数合わせのための水増しはしない。
- ビジネスロジックをモックしない。モックは外部 I/O（HTTP通信、DB接続、ファイルシステム）のみ。
- `toBeTruthy()` 等の曖昧なアサーションを避け、具体的な値で検証する。
