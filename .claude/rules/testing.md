# テストルール

## テスト分類

| 分類 | 定義 |
| ------ | ------ |
| 正常系（Normal） | 期待通りの入力 → 正しい結果 |
| 準正常系（Semi-Normal） | 想定内の異常入力 → 適切なハンドリング |
| 異常系（Abnormal） | 想定外のエラー → 安全な失敗 |

## テストの粒度（分類と直交する軸）

上の分類（何を入れて何が返るか）とは別に、**どこまでのレイヤを通すか**を区別する。詳細・各アプリの実体は `docs/08` を参照。

| 粒度 | 定義 |
| ------ | ------ |
| 単体（Unit） | 1 レイヤ/クラスの契約を隔離して検証 |
| IT（統合／結合） | ルーティング→コントローラ→認証→データアクセス→実 DB を横断で検証 |
| E2E | ブラウザ自動化で UI から通しで検証 |

## 原則

- テストは仕様の証明。テストが失敗したら実装を修正する（テストを実装に合わせない）。
- 異常系（準正常系 + 異常系）が正常系を上回ることを目安とする。比率の数値目標より、**認可・境界値・不正入力**を優先的にカバーすることを重視し、数合わせのための水増しはしない。
- ビジネスロジックをモックしない。モックは外部 I/O（HTTP通信、DB接続、ファイルシステム）のみ。
- `toBeTruthy()` 等の曖昧なアサーションを避け、具体的な値で検証する。

## テスト対象・テスト DB の接続先（破壊防止）

**テストは「既存データを壊してよい環境」だけを向く。** テストは登録・作成・削除を繰り返すため、接続先を誤ると消えて困るデータ（共有 MySQL）や無関係な環境を壊す。保護対象の定義は [production-data.md](./production-data.md) を参照。

- **PHPUnit（Laravel の Feature / 単体、laminas の IT / 単体）は SQLite in-memory を使う。** `phpunit.xml` の `DB_CONNECTION=sqlite` / `DB_DATABASE=:memory:` を外して共有 MySQL を向けない（`RefreshDatabase` は全テーブルを DROP するため、3 アプリ分のデータが消える）。
- **E2E（Playwright）の対象 URL は allowlist で検証する。** ホストが `localhost` / `127.0.0.1` / `::1` 以外なら、**テストが 1 件も走る前に**落とす。解決は 1 箇所（`e2e/helpers/config.ts`）に集約し、全 project がその入口を通す。
- **失敗メッセージに「解決されたホスト」と「復旧手順」を含める。** 原因の特定に時間をかけさせない。
- **`process.env.X ?? ローカル既定` というフォールバックだけで安全を担保しない。** 「未設定なら安全側」に見えて、**値が入っていれば危険側**に倒れる。既定値は利便性のためのものであり、安全性の判定は allowlist（通すものを列挙し、他は落とす）で行う。
- **ガード自体をテストする**（既定値・`localhost` 系の許可・リモートの拒否・メッセージの内容）。ガードが壊れても他のテストは緑のままになるため、明示的に検証しないと機能停止に気づけない。

> **テストが不可解に全滅したら、まず接続先を疑う。** 原因を推測で決めつけて環境変数を手で固定し、先に進めてはならない（[production-data.md](./production-data.md) の「エラーの回避策として接続先を変更しない」）。
