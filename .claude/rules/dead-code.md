# デッドコード禁止

**使われていないコードを残さない。** 消したコードは Git の履歴に残っており、必要になれば復元できる。**「復元できる」ことが、消してよい根拠である。**

## 削除するもの

| 種類 | 例 |
|---|---|
| **コメントアウトされたコード** | `// $old = ...` の塊、旧実装の丸ごとコメントアウト |
| **未使用の変数・関数・クラス・定数** | どこからも参照されないもの |
| **未使用の public メソッド** | 公開しているが誰も呼んでいないもの |
| **到達不能コード** | `return` 後の処理、常に false の条件分岐 |
| **未使用の依存パッケージ** | `composer.json` / `package.json` に残るだけのもの |
| **使われないフィーチャーフラグ** | 恒久的に true（または false）で固定され、分岐の片側が死んでいるもの |
| **スキップされたままのテスト** | `markTestSkipped()` / `@group skip` / Playwright の `test.skip` が放置されているもの |
| **旧実装** | 新実装に切り替えた後も「念のため」残している関数・ファイル |

## 「将来使うかもしれない」を残さない

- **今どこからも呼ばれていないコードは削除する。** 「あとで使う」「参考に残す」は理由にならない。**必要になった時点で書く方が、腐ったコードを直すより速い**。
- 使われていないコードは**保守コストだけを払い続ける**（リファクタ・依存更新・型変更のたびに巻き込まれ、レビューでも読まれ、検索結果を汚す）。
- **動いていないコードは壊れているかどうかも分からない**。テストもされないまま残り、いざ使おうとすると動かない。
- コメントアウトで残さない。**残す必要があるのは「なぜそうしなかったか」であり、それはコードではなくコメント・コミットメッセージ・issue で表現する**。

## 例外（残してよいもの）

以下は「未使用に見えるが必要」なもの。**削除する前に確認する**。

- **フレームワークの規約・DI 経由で呼ばれるもの**。静的解析が「未使用」と誤検出しやすい。本プロジェクトでは特に次が該当する。
  - Laravel: マイグレーション、シーダー、ルート定義から解決されるコントローラのアクション、Eloquent の `$fillable` / `$casts` / リレーションメソッド、Blade から参照されるアクセサ。
  - Laminas: `*Factory` から生成されるコントローラ・サービス（`module.config.php` の `service_manager` / `controllers` 経由）、PHTML から呼ばれるビューヘルパー、`InputFilter` の定義。
- **3 アプリの読み比べのために意図的に揃えている実装**。`apps/laravel-fullstack` / `apps/laravel-api` / `apps/laminas` は同一題材の対比が目的であり、片方でしか使われないように見えても対応関係のために残す場合がある。**その場合は理由をコメントに書く**。
- **段階的移行の途中**で、削除時期が決まっているもの。**期限と削除条件をコメントに書き、issue を立てて追跡する**（書かないなら残さない）。
- **意図的に残す将来用のインターフェース**は、**その判断と理由をコメントに書く**。書けないなら残さない。

## 検出

- 静的解析の未使用検出を活用する（Larastan / Psalm の未使用変数・到達不能コード検出）。詳細な運用は [static-analysis.md](./static-analysis.md) に従う。
- **未使用の public メソッドは通常の解析では検出しにくい**。Psalm の `--find-dead-code`（`UnusedMethod` / `PossiblyUnusedMethod`）等の横断検出の利用を検討する。ただしフレームワーク規約経由の呼び出しを誤検出するため、上記「例外」と突き合わせて判断する。
- **未使用の依存は `composer why-not` / 手動棚卸しで確認する**。`composer.json` に残るだけのパッケージを放置しない。
- **カバレッジ 0% の行はデッドコードの候補**。テストカバレッジレポートを、未使用コードの発見にも使う。

## レビュー観点

- コメントアウトされたコードが含まれていないか（**指摘したら削除する。「残しておいて」は受け入れない**）。
- 「将来のため」に追加された、今どこからも呼ばれない関数・引数・オプションがないか。
- 置き換え実装を入れた PR で、**旧実装が削除されているか**（新旧併存のまま終わっていないか）。
- スキップされたテストが放置されていないか。
