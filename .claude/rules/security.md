詳細な実装仕様は `docs/06-security-specification.md` に置く。本ルールは**常に守る最低線**を定める。

**関連ルールとの分担**（重複させない）:

## 認証・認可

- 認証方式はアプリごとに定める（fullstack = セッション / api = Sanctum トークン / laminas = laminas-authentication）。詳細は [php.md](./php.md)。
- **エンドポイントごとにアクセス制御を明示する**（公開 / 認証必須）。「ミドルウェアを付け忘れたら公開になる」実装にしない。
- **認可は所有者スコープを必ず通す**。一覧・単発取得の両方でログインユーザー本人に限定する（実装は [php.md](./php.md)、レスポンスは [error-handling.md](./error-handling.md)）。

## 通信・アクセス制御

- 本番の全通信は **HTTPS** を必須とする。
- **CORS** は許可するオリジンを明示的に指定する（`*` は本番で使用しない）。
- **レートリミット** を導入する（ログイン・トークン発行など認証系エンドポイントは特に厳しく制限）。

### 本プロジェクトでの適用範囲

本リポジトリは学習用でローカル compose のみを持ち、**本番環境が存在しない**（[production-data.md](./production-data.md) と同じ前提）。上記 3 項目のうち、実装するもの・妥協として記録するものを次のとおり定める（issue #68）。

| 項目 | 本リポジトリでの扱い |
| --- | --- |
| HTTPS | **妥協**。ローカルは HTTP で動かす。Cookie の `Secure` 属性を含む詳細は `docs/06` の「既知の注意点」 |
| レートリミット | **実装する**。ブルートフォース耐性は本番の有無に関係なく題材として意味があり、3 アプリのスタック差分が最も出る箇所でもある（Laravel = `RateLimiter` ファサード / laminas = 自前実装） |
| CORS | **妥協**。別オリジンからのブラウザアクセスが 1 つも無く、設定しても誰も通らない（`.claude/rules/dead-code.md` の「将来使うかもしれないものを残さない」）。理由は `docs/06` に記録する |

**妥協にした項目は必ず `docs/06` に理由付きで記録する。** ルールに書いてあるのに実装が無く、記録も無い状態を残さない。

## インジェクション対策

多層防御とし、1 層の漏れが即脆弱性にならないようにする。

- **SQL インジェクション**: Eloquent / TableGateway のバインドパラメータを必須とする。生 SQL の文字列結合は禁止（[php.md](./php.md)）。
- **XSS**: 出力エスケープを必須とする（Blade の `{{ }}` / PHTML の `escapeHtml()`）。`{!! !!}` やエスケープなし出力は、**理由をコメントに書いた上で**入力側のサニタイズと併用する。CSP ヘッダーを併せて設定する。
- **CSRF**: セッション認証（fullstack / laminas）の web フォームは CSRF トークン必須（`@csrf`）。Bearer Token 認証で Cookie を使わない laravel-api は不要。

## シークレット管理

- ローカル環境: `.env`（`.gitignore` 済み。コミットしない）。雛形は `.env.example` を更新する。
- 本番環境: Secret Manager 等のマネージドサービスを使用する。
- 認証情報・鍵をコードにハードコードしない（既知の妥協点は `docs/06` に明記されているものに限る）。

## 依存の脆弱性

- 依存を更新したら `composer audit` を実行し、クリーンを維持する（[coding-standards.md](./coding-standards.md)）。
- 解消済み CVE の再発を監視する（詳細は `docs/06`）。

## レビュー観点

- 新規エンドポイントに認証ミドルウェアと所有者スコープが両方付いているか。
- エスケープなし出力（`{!! !!}` 等）に理由が書かれているか。
- ログ・エラーレスポンスにパスワード・トークンが混入していないか。
