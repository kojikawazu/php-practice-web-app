# 静的解析の運用

使用するツールは [coding-standards.md](./coding-standards.md) の「Lint / Format（アプリ別）」で定める（Laravel = Pint + Larastan / Laminas = phpcs + Psalm）。本ルールは**どう運用するか**を定める。

## 役割分担（重ねない）

| 種類 | 役割 | 議論の対象 |
| --- | --- | --- |
| **Formatter** | 見た目（インデント・改行・引用符）を機械的に統一する | **しない**。デフォルト設定に従う |
| **Linter** | バグの温床・危険なパターンを検出する | ルールの追加・除外のみ議論する |
| **型チェッカ** | 型の不整合を検出する | しない |

- **見た目に関する Linter ルールを有効にしない**。Formatter と競合し、直しても直らないエラーが発生する（Laravel は Pint にフォーマットを任せ、Laminas は phpcs のフォーマット系を phpcbf で解決する）。
- **フォーマットの好みを議論しない・レビューで指摘しない**。Formatter の出力が正である。フォーマット指摘が出る状態なら、それは CI の設定不足である。

## CI で必須にする

- **Linter・Formatter・型チェックはすべて CI で実行し、違反があればマージをブロックする**。ローカル任意実行にしない（本プロジェクトは `lint` ジョブが Pint `--test` / Larastan / phpcs / Psalm を実行する）。
- **警告（warning）を放置しない**。「警告は出るが動く」状態が常態化すると、新しい警告が埋もれて検出装置として機能しなくなる。**警告ゼロを維持**し、守れないルールは有効にしない（`error` にするか、無効にするかの二択）。
- Formatter は**差分ゼロを検証**する（`pint --test` / `phpcs`）。CI がコードを自動整形してコミットし返す運用にしない。
- 型チェック（静的解析）は**テストとは別に明示実行**する（`composer analyse` / `vendor/bin/psalm`）。テストが通ることを型の担保にしない。

## baseline の扱い

既存指摘を baseline（`apps/laravel-*/phpstan-baseline.neon` / `apps/laminas/psalm-baseline.xml`）に記録し、**新規に増えた指摘のみ CI を失敗させる**運用を採る。

- **baseline は「凍結」ではなく「返済計画」**。段階的に減らすことを前提とし、増やす方向の更新は原則行わない。
- 新規コードの指摘を baseline に追記して回避しない。**baseline へ追記するのは、既存コードの大規模改修時など理由を説明できる場合のみ**とし、PR 説明に理由を書く。
- baseline を再生成するときは**差分を必ず確認する**（無関係な指摘がまとめて消える／増えるのを見逃さない）。

## 抑制コメントの扱い

`@phpstan-ignore-next-line` / `@psalm-suppress` / `phpcs:ignore` などの抑制は、**例外的な手段**として扱う。

- **理由をコメントで必ず書く**。「なぜこのルールを守れないのか」「いつ解消できるのか」を書く。理由のない抑制は差し戻す。
- **範囲を最小にする**。ファイル全体ではなく**該当行のみ**を抑制する（`@phpstan-ignore-next-line` / `phpcs:disable` … `phpcs:enable` の対で範囲を閉じる）。ファイル先頭での一括無効化をしない。
- **抑制するルールを明示する**（`@psalm-suppress PossiblyNullReference` のように**ルール名を書く**）。ルール名なしの全ルール抑制をしない。
- 同じ抑制が**何箇所にも増えたらルール設定自体を見直す**。プロジェクトの実態に合っていないルールを、抑制コメントで回し続けない。

## ルール設定の変更

- **ルールの追加・除外はプロジェクト全体の合意で行い、設定ファイルに理由をコメントで残す**。個人の好みで一時的に緩めない。
- 既存コードへ厳しいルールを導入して大量の違反が出る場合、**一括抑制せず段階導入する**（baseline に記録して新規のみ対象にする、期限を決めて解消する）。
- 設定ファイル（`pint.json` / `phpstan.neon` / `phpcs.xml` / `psalm.xml`）は**コミット対象**。ローカル固有設定に依存しない。

## エディタ・コミット時

- **エディタの保存時フォーマットを有効にする**（CI で落ちる前に手元で解決する）。
- pre-commit フックを使う場合は**高速なもの（変更ファイルのみの format / lint）に限定**する。テストや全体解析を含めるとコミットが重くなり、`--no-verify` が常態化する。
- **フックは CI の代替にならない**。スキップ可能なため、最終的な担保は必ず CI に置く。

## レビュー観点

- 抑制コメントに理由が書かれているか。範囲・ルール名が最小限に絞られているか。
- Formatter が直すべき見た目をレビューで指摘していないか（＝設定不足のサイン）。
- 警告が出たまま放置されていないか。
- baseline が新規指摘の逃げ道に使われていないか。
