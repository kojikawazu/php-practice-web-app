# データ保護（破壊的操作の下限）

**データを壊す事故は、悪意ではなく「接続先を間違えたまま普段どおりの操作をした」ときに起きる。** 本ルールは、データを不可逆に失い得るすべての経路に共通の下限を定める。

## 本リポジトリでの保護対象（適用範囲）

本リポジトリは学習用でローカル compose のみを持ち、**本番環境は存在しない**。そのため「本番 DB」に相当する保護対象を次のとおり読み替える。

| 保護対象 | 実体 | 壊れると何が起きるか |
| --- | --- | --- |
| 共有 MySQL `php_practice` | compose の `mysql` サービス（`docker/mysql/data/` に永続化） | 3 アプリが prefix（`fs_` / `api_` / `lam_`）で 1 つの DB を共有しているため、**1 アプリの操作ミスで他 2 アプリのデータも消える**（`docs/05`） |
| アップロード済み画像 | 各アプリの `storage/`（`docs/05` の不変条件「`image_path` は必ず実在する」） | DB とファイルの整合が崩れ、復旧できない |

将来この題材を本番相当の環境へ載せる場合は、本ファイルの原則を**そのまま本番に読み替えて適用する**。

## 原則

- **接続先を毎回明示的に確認する。**「たぶんローカルを向いている」で破壊的操作を実行しない。
- **破壊的操作を通常運用に組み込まない。** 共有 MySQL に対して次を実行しない。
  - `TRUNCATE` / `DROP` / 条件なしの `DELETE`・一括 `UPDATE`
  - `php artisan migrate:fresh` / `migrate:refresh` / `db:wipe`
  - `docker compose down -v`（`docker/mysql/data/` ごと消える。停止は `make down` を使う）
- **スキーマ変更はマイグレーションファイル経由で行い、PR に載せる。** コンテナに入っての手打ち SQL や管理ツールからの直接変更を運用手段にしない。
- **エラーの回避策として接続先を変更しない。**「テストが落ちるから接続先を書き換えて通す」「繋がらないから別の DB を向ける」は禁止。**原因を報告して止まる。**
- **復旧手段を先に確認する。** 共有 MySQL は `make setup`（`scripts/setup.sh`）でスキーマを再構築できるが、**入っていたデータは戻らない**（バックアップを取っていない）。消えて困るデータを置かない。

## AI エージェント（Claude Code / Codex / MCP）に対する制約

自動化されたエージェントは**接続先を確認しないまま操作を完了できてしまう**ため、人間より強い制約を課す。

- **MCP の DB 操作ツール（`execute_sql` / `apply_migration` 等）を本リポジトリの作業に使わない。** 本リポジトリの DB は compose の MySQL であり、MCP が繋がる先（外部のマネージド DB 等）は**無関係な資産**である。取り違えは他プロジェクトのデータ破壊になる。参照系（テーブル一覧・ログ）も、本リポジトリの作業では必要にならない。
- 上記「原則」で禁止した操作が必要になった場合は、**実行前に接続先と実行内容を提示し、1 操作ごとに明示承認を得る**。以前の承認を次の操作へ流用しない。
- マイグレーションは**ファイルを生成して PR に載せる**。エージェントが DB へ直接 DDL を流さない（`make migrate` の実行は通常運用として可）。
- **git の不可逆操作も同じ扱いとする**（`push --force` / `reset --hard` / 追跡ブランチの削除）。マージ済みブランチの削除は `pr-approved` の手順の範囲で行う（[git.md](./git.md)）。

## 取り込まなかった項目（と理由）

本ルールは共通テンプレート（`my-custom-skills` の `production-data.md`）を土台に、**本リポジトリで実効性のある部分だけ**を取り込んでいる。次は意図的に除外した。

| 除外した項目 | 理由 |
| --- | --- |
| 本番 / 開発 / プレビュー環境の分離、非本番への本番データ持ち込み（マスキング） | 本番・開発環境が存在せず、分離すべき対象が無い |
| 本番 DB を修正する例外手順（dry-run → PITR の復旧ポイント確認 → 冪等スクリプト → トランザクション実行） | 本番 DB が無く空転する。**「将来使うかもしれない」ものを残さない**方針（[dead-code.md](./dead-code.md)）をルール文書にも適用する。本番相当の環境を持った時点でテンプレートから取り込む |
| メール一斉送信・決済 API・オブジェクトストレージなど本番リソースの保護 | 3 アプリに外部送信・課金の機能が無く、画像も compose 内のローカルストレージのみ |
