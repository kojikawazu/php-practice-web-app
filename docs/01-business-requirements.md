# 01. 要求仕様書（Business Requirements）

プロジェクトの背景・目標・スコープなど、「なぜ作るのか」を定義する。

## 背景・課題

PHP の主要フレームワークを横断的に学習したいが、フレームワークごとに別リポジトリを用意すると環境構築や比較が煩雑になる。1 つのリポジトリで複数フレームワークを同じ題材（タスク管理）で実装し、設計や API の違いを比較しながら学べる場が欲しい。

## 目標（ゴール）

- Laravel（フルスタック / API）と Laminas を **1 つのモノレポ**で動かし、同一機能を各フローで実装して比較学習できる。
- Docker だけで誰でも同じ環境を再現できる（ホストに PHP/Composer 不要）。
- 各アプリにテストと CI を備え、変更時の回帰を自動検知できる。
- 成功の目安: `docker compose up` で 3 アプリが起動し、CI（3 スイート）が green に保たれていること。

## ステークホルダー

| 役割 | 説明 |
|------|------|
| 学習者（兼開発者） | 本リポジトリで PHP フレームワークを学ぶ本人 |
| レビュアー | PR をレビュー・マージする人間（自動マージ禁止） |
| AI アシスタント | 設計・実装・PR 作成を補助（マージ権限は持たない） |

## スコープ

**やること**

- 3 アプリ共通の「タスク管理」機能（CRUD・編集・複製・完了切替・検索・ページネーション・開始日/終了日）
- 認証（fullstack/laminas はセッション、api は Sanctum トークン）とユーザー単位のデータ分離
- Docker Compose による実行環境、GitHub Actions による CI

**やること（追加）**

- E2E テスト（Playwright）で 3 アプリの主要フロー（登録→ログイン→CRUD）を実環境で検証（当初スコープ外から格上げ。`docs/08` / `docs/11 #13`）

**やらないこと（Out of Scope）**

- 本番デプロイ・独自ドメイン運用・スケーリング
- 高度な権限管理（ロール/RBAC）、SSO、メール送信
- デザイン作り込み

## 制約

- 学習用ローカル環境前提（認証情報は開発用の平文で可、本番化時に要見直し）。
- 技術: PHP 8.3 / Laravel 12 / Laminas MVC / MySQL 8 / nginx / Docker。
- 開発フローは GitHub Flow（main 直接コミット禁止、PR 経由、マージは人間）。
