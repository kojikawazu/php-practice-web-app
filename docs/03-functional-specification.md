# 03. 機能仕様書（Functional Specification）

各機能が「どう動くか」を詳細に定義する。

## 機能詳細

| 機能 | 入力 | 処理 | 出力 |
| ------ | ------ | ------ | ------ |
| 登録 | name(api以外)/username, email(Laravel)/—, password | ユーザー作成・ログイン | タスク一覧へ遷移 / トークン(api) |
| ログイン | 認証情報 | 照合（bcrypt）→ セッション/トークン発行 | 一覧へ遷移 / トークン |
| タスク作成 | title, start_date?, end_date? | 検証 → user_id 付きで保存 | 一覧へ遷移 / 201(api) |
| 編集 | title, start_date?, end_date? | 所有者確認 → 更新 | 一覧へ遷移 / 200(api) |
| 複製 | 対象 id | 所有者確認 → 「（コピー）」+日付コピーで新規作成 | 一覧へ遷移 / 201(api) |
| 検索/ページ | q, page | user_id でスコープし LIKE 検索・件数分割 | 絞り込み済み一覧 |

## ユーザーフロー

- 未ログインで保護ページ（`/tasks` 等）へアクセス → ログイン画面へ誘導
- `/register` でユーザー登録 → 自動ログイン → タスク一覧
- `/login` でログイン → タスク一覧（自分のタスクのみ表示）
- タスクの追加・編集（タイトル変更）・複製（「（コピー）」付きで作成）・完了切替・削除（自分のタスクのみ）
- 追加・編集・複製は**確認画面（2ステップ）**を経て確定する（fullstack）。確認画面で内容・画像名・URLプレビューを表示し、確定/キャンセルを選ぶ（キャンセルで一時保存の画像も破棄）
- タスクに開始日・終了日（任意）をカレンダー（flatpickr）で設定。終了日は開始日以降のみ許可
- 一覧はタイトル検索（`q`）とページネーション（5 件/ページ、`page`）に対応
- ログアウト → ログイン画面
- api はトークン認証: `register`/`login` で取得した token を Bearer 送信

## UI/UX 仕様

- 画面: ログイン / 新規登録 / タスク一覧（追加・検索・ページャ）/ タスク編集（fullstack・laminas）。api は JSON のみ。
- タスクに画像を 1 枚添付できる（任意・fullstack/api）。**最大 2MB**（超過はアプリのバリデーションで拒否。層ごとの上限と 413 / 422 の境界は `docs/07`）。画像は公開ディレクトリ外に保存し、**所有者のみ**アプリ経由で閲覧可。
- タスクに URL を登録すると、サーバーが**安全に**（SSRF 対策付き）取得して OGP プレビュー（タイトル/画像）をカード表示する（任意・fullstack）。
- 画面は Tailwind CSS（Play CDN・Node不要）で簡易スタイリング（fullstack / laminas）。
- 日付入力は flatpickr のカレンダー（`Y-m-d`）。
- バリデーションエラーはフォーム上部に一覧表示（Laravel は `$errors`、Laminas は InputFilter メッセージ）。
- 完了タスクは取り消し線で表示。期間がある場合は `[開始 〜 終了]` を併記。

## ビジネスロジック

- タスクは作成ユーザーに所有され、本人のみ閲覧・更新・複製・削除できる（他人のは Laravel=404 / Laminas=対象外）。
- タイトルは必須・255 文字以内。複製時のタイトルは「（コピー）」付与で 255 文字に丸める。
- 開始日・終了日は任意。両方が設定される場合は「終了日 ≥ 開始日」。api の部分更新（PATCH）では**更新後に確定する組**で判定し、リクエストに無い側は保存済みの値で補う（`docs/07`）。複製では `done` を false にリセット。
- 画像の保存・差し替え・削除は、ファイルと DB の**どちらかが失敗しても DB に実在しない `image_path` を残さない**（順序と補償の規約は `docs/05`）。失敗時は 500 を返し、ユーザーの画像は失われない。
- ログアウト・完了切替・複製・削除は状態を変えるため POST で実行する（laminas は GET を 405 で拒否）。全 POST フォームは CSRF トークン必須（`docs/06`）。
- 共有 DB でアプリ間のデータはテーブルプレフィックスで分離。
