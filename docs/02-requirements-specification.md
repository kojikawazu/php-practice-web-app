# 02. 要件仕様書（Requirements Specification）

要求を満たすために「何を実現するか」を機能要件として一覧化する。実装は 3 アプリ（laravel-fullstack / laravel-api / laminas）共通。

## 機能要件一覧

| ID | 機能名 | 概要 | 優先度 |
|----|--------|------|--------|
| F-01 | ユーザー登録 | 新規ユーザーを作成しログイン状態にする | Must |
| F-02 | ログイン / ログアウト | 認証情報でログイン、セッション/トークンを発行・破棄 | Must |
| F-03 | タスク一覧 | ログインユーザー本人のタスクのみ表示 | Must |
| F-04 | タスク作成 | タイトル（必須）でタスクを追加 | Must |
| F-05 | タスク編集 | タイトルを変更 | Must |
| F-06 | 完了切替 | 完了/未完了をトグル（fullstack/laminas）| Should |
| F-07 | タスク削除 | 自分のタスクを削除 | Must |
| F-08 | タスク複製 | 既存タスクを「（コピー）」付きで複製 | Could |
| F-09 | タイトル検索 | タイトル部分一致で絞り込み | Should |
| F-10 | ページネーション | 一覧を 5 件/ページで分割 | Should |
| F-11 | 開始日・終了日 | 任意の期間をカレンダーで設定（終了日≥開始日）| Should |
| F-12 | API トークン管理 | トークンの一覧・発行・失効・有効期限（api のみ）| Could |

## 受け入れ条件（抜粋）

- F-02: 誤った認証情報ではログインできず、エラーが表示される。期限切れトークンは 401。
- F-03/F-07: 他人のタスクは閲覧・操作できない（Laravel は 404、Laminas は対象外として無視）。
- F-04/F-05: 空タイトルは保存できずバリデーションエラーになる。
- F-11: 終了日が開始日より前の場合は保存できない。不正な日付形式は拒否。
- 各要件は対応する自動テスト（または laminas はライブ smoke）で検証される。

## 優先度・前提

- 優先度は MoSCoW（Must / Should / Could）。
- 前提: ログイン必須（未認証は認証画面へ誘導）。データはユーザー単位に分離。
- 共有 MySQL をアプリ別テーブルプレフィックス（`fs_` / `api_` / `lam_`）で名前空間分離する（詳細は `05-data-specification.md`）。
